Getting Started

Introduction

Syncra is an offline-first sync engine that lets you build applications that work seamlessly without a network connection. It manages local state in IndexedDB, queues operations when offline, and automatically syncs to your backend when connectivity is restored.

The SDK handles conflict resolution, exponential backoff retries, and delta synchronization so you can focus on building features instead of managing network state.

Installation

Install the Syncra SDK via npm or your preferred package manager:

terminal
$ npm install syncra-sdk

Quick Start

Initialize the SDK once at your app entry point. Use apiKey for project-level access or bearerToken for user-authenticated requests:

syncra-init.ts 
import { SyncraSDK } from 'syncra-sdk';

const sdk = new SyncraSDK({
  baseUrl: 'https://syncra-bwd0.onrender.com',
  apiKey: 'your-api-key',       // from your project dashboard
  syncInterval: 30000,
});

await sdk.initialize();
await sdk.createRecord({ title: 'My note' });

sdk.on('sync-complete', ({ applied }) => {
  console.log(`Synced ${applied} records`);
});

Or authenticate as a user with a JWT bearer token:

syncra-init.ts 
const sdk = new SyncraSDK({
  baseUrl: 'https://syncra-bwd0.onrender.com',
  bearerToken: 'your-jwt-token',  // from login response
  syncInterval: 30000,
});

await sdk.initialize();

SDK Reference

SyncraSDK

The main class. Instantiate once and reuse throughout your application.

new SyncraSDK(options: SyncraOptions)
Option Type Description
baseUrlstringYour Syncra API endpoint
apiKeystringProject API key (from your dashboard). Use this or bearerToken
bearerTokenstringJWT bearer token for user-authenticated requests
userIdstringOptional user ID sent as x-user-id header
syncIntervalnumberAuto-sync interval in ms (default: 30000)

You can also update credentials at runtime:

sdk.setApiKey('new-api-key');
sdk.setBearerToken('new-jwt-token');
sdk.setUserId('user-id');

API Keys

API keys are project-scoped credentials generated from your dashboard. They are sent via the x-api-key header on every sync request.

example 
const sdk = new SyncraSDK({
  baseUrl: 'https://syncra-bwd0.onrender.com',
  apiKey: 'syncra_pk_live_xxxxxxxxxxxx',
});

// Update the key at runtime (e.g. after project creation)
sdk.setApiKey('syncra_pk_live_new_key');
info

Generate and manage API keys from your Dashboard. API keys follow the format syncra_pk_live_... and are sent as the x-api-key header on every sync request. If both apiKey and bearerToken are provided, apiKey takes precedence.

createRecord

Creates a new record locally and queues it for sync. Returns immediately — no network required.

sdk.createRecord(data: Record<string, unknown>): Promise<LocalRecord>

updateRecord

Updates an existing record locally and queues the update for sync. Throws if the record does not exist.

sdk.updateRecord(id: string, data: Record<string, unknown>): Promise<LocalRecord>

deleteRecord

Deletes a record locally and queues the deletion for sync. Throws if the record does not exist.

sdk.deleteRecord(id: string): Promise<void>

getRecords

Returns all records currently in the local in-memory cache. Call initialize() first to restore records from IndexedDB on app load.

sdk.getRecords(): LocalRecord[]

getPendingOperations

Returns all operations that are queued and waiting to be synced to the server.

sdk.getPendingOperations(): LocalQueuedOperation[]

sync()

Manually trigger a sync cycle. Pushes queued operations to the server and pulls remote updates. No-op when offline.

sdk.sync(): Promise<SyncResult>

isOnlineState

Returns the current network connectivity state.

sdk.isOnlineState(): boolean

onConflict

Register a custom conflict resolution handler. If not set, the server version wins. The handler receives both versions and must return the resolved data and version to use.

conflict-handler.ts 
sdk.onConflict((conflict) => {
  // conflict.recordId      — which record conflicted
  // conflict.clientVersion — your local version number
  // conflict.serverVersion — server's version number
  // conflict.serverData    — server's current data

  return {
    data: { ...conflict.serverData, ...myLocalOverrides },
    version: conflict.serverVersion,
  };
});

destroy

Cleans up network listeners and stops the auto-sync interval. Call this on logout or when tearing down the SDK instance.

sdk.destroy(): void

Events

Subscribe using sdk.on(event, handler).

sync-start

Fired when a sync cycle begins.

sync-complete

Fired after a successful sync. Payload: { applied: number, rejected: number }

sync-failed

Fired when a sync cycle encounters an error. Payload: { error: Error }

conflict

Fired when a conflict is detected during sync. Payload: { recordId, clientVersion, serverVersion, serverData }

online

Fired when connectivity is restored. A sync is triggered automatically.

offline

Fired when the device goes offline. Writes continue to work locally.

API Reference

Authentication

API requests accept two authentication methods. Use one per request:

API key — project-scoped, generated from your dashboard:

x-api-key: syncra_pk_live_xxxxxxxxxxxx

Bearer token — JWT from the login response, for user-authenticated requests:

Authorization: Bearer <your-jwt-token>
info

If both headers are present, x-api-key takes precedence.

POST /sync

Push a batch of queued operations to the server. Processed atomically with idempotency keys.

request.json 
{
  "operations": [{
    "id": "op_abc123",
    "type": "create",
    "recordId": "rec_xyz789",
    "payload": { "title": "My note" },
    "version": 1,
    "idempotencyKey": "idem_abc123"
  }]
}

GET /sync/updates

Fetch remote updates since a given timestamp. Returns delta records only.

GET /sync/updates?since=1704067200000
